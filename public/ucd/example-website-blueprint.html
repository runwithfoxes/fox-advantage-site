A change to my website
One plain request, "change this on the site", runs through the same set of steps every time. Here is what actually happens between the ask and it going live.
The ask
1
Read the rules first
Before touching anything, it reads the brand and how the site is built.
2
Check what's in flight
Looks at what's already changed and unfinished, so nothing gets clobbered.
3
Make the change
Edits the site itself: the layout, the words, whatever was asked for.
Words changed
Runs it through my writing voice. Plain, my words, no jargon or filler.
Layout only
Nothing to reword, straight on.
4 The brand check
Check it against the brand
Colours, fonts, spacing and tone, all matched to the guidelines.
It doesn't move on until it matches the brand.
5
Build it and look
Builds the site, opens the page, takes a screenshot and actually looks at it.
No "it's done" off the code alone. It has to see the real page rendered before it says a word.
6 My call
I look at it and decide
Seen at real size, not a big preview. Yes, or send it back.
Nothing goes live until I approve it.
7 Push it live
Save it, then deploy to Vercel
The change is saved, backed up, and pushed to the service that runs the site.
It won't deploy with anything unsaved or not backed up first.
8
Check it's really live
Opens the real site and confirms the change is actually there.
